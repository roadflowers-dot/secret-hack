브리핑

이 사이트는

웹 해킹 기법이 어떻게 동작하는지 직접 눌러 보고, 어떻게 막는지를 같은 화면에서 비교하는 훈련장입니다. 각 실습에는 두 가지 모드가 있습니다.

● VULNERABLE 모드

흔히 보는 취약한 코드. 공격이 성공하는 모습을 볼 수 있습니다.

● SECURE 모드

올바른 방어 코드. 같은 공격이 막히는 것을 확인합니다.

안전 장치

  • SQL 실습은 요청마다 새로 만드는 메모리 DB(읽기 전용)에서 실행됩니다.
  • XSS 결과는 sandbox iframe + CSP sandbox 로 격리되어 이 사이트의 쿠키·세션에 접근할 수 없습니다.
  • 경로 탐색 실습은 가짜 파일 시스템입니다. 실제 서버 파일은 읽지 않습니다.
  • 비밀번호 실습은 브라우저 안에서만 계산하며 서버로 전송하지 않습니다.

규칙

여기서 배운 기법을 허가받지 않은 시스템에 사용하는 것은 불법입니다 (정보통신망법 제48조 등). 실습은 이 사이트 안에서만 하세요. 모든 실습 기록은 보안 로그에 남습니다.

01 // SQL Injection

OWASP Top 10 — A03: Injection · 위험도: 치명적

공격 원리

사용자 입력을 SQL 문자열에 그대로 이어 붙이면, 입력값이 데이터가 아니라 코드로 해석됩니다. ' OR '1'='1 한 줄로 비밀번호 검사를 통째로 건너뛰거나, UNION SELECT 로 다른 테이블을 읽을 수 있습니다.

방어 방법

  • Prepared Statement(파라미터 바인딩) — 입력은 항상 데이터로 취급
  • ORM / 쿼리 빌더 사용
  • DB 계정 최소 권한, 에러 메시지 숨기기
  • 입력 길이·형식 검증 (보조 수단)
// ✗ 취약
db.query("SELECT * FROM users WHERE username = '" + u + "' AND password = '" + p + "'")
// ✓ 안전
db.prepare("SELECT * FROM users WHERE username = ? AND password = ?").all(u, p)

02 // Cross-Site Scripting (XSS)

OWASP Top 10 — A03: Injection · 위험도: 높음

공격 원리

게시판·댓글 등에 입력한 HTML이 그대로 페이지에 삽입되면, 공격자의 자바스크립트가 다른 사용자의 브라우저에서 실행됩니다. 세션 쿠키 탈취, 키 입력 가로채기, 가짜 로그인 창 띄우기가 가능합니다.

방어 방법

  • 출력 시 HTML 이스케이프 (< → &lt;)
  • innerHTML 대신 textContent
  • 리치 텍스트는 DOMPurify 같은 sanitizer
  • CSP로 인라인 스크립트 금지, 쿠키에 HttpOnly
// ✗ 취약
el.innerHTML = comment;
// ✓ 안전
el.textContent = comment;     // 또는 escapeHtml(comment) + CSP: script-src 'self'
